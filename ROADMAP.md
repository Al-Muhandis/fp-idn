# ROADMAP — fp-idn

Дорожная карта доработок библиотеки по итогам код-ревью (2026-11-14).
Все факты в этом документе **проверены** прогоном тестов и зондовых программ,
а не получены только чтением кода.

**Как пользоваться:** в новой сессии напишите «Делай этап N из ROADMAP.md».
Сессия должна прочитать этот файл, выполнить один указанный этап и в конце
этапа отметить его в чек-листе ниже. Этапы выполнять по порядку — у них есть
зависимости (кроме случаев, когда явно указано «независим»).

## Этап 1 — 64-битная арифметика в encode/decode

**Цель:** устранить переполнение 32-битного `Cardinal`, из-за которого
кодировщик выдаёт неверный вывод, а декодер — молча мусор.

**Зависимости:** Этап 0 (нужен стресс-тест).

### Контекст (проверено зондами)

- `fppunycode.pas`, encode, строка ~254: `aDelta += (M - N) * (aHandledLen + 1)`
  переполняется при `(M-N)*(h+1) >= 2^32` (минимум ~4000 кодовых точек
  с широким разбросом). На конструкции из Этапа 0 (60k точек) выдаёт
  60013 вместо 60015, round-trip ломается. RFC 3492 §6.4 требует
  контролировать переполнение.
- Decode, строки ~348/360: `I += aDigit * W` и `W *= (_BASE - T)` не
  имеют защитных проверок. Для входа `99999999999999999999` (20 девяток,
  каждая цифра ≥ t) `W` растёт ×10 за шаг и уходит за 2^32 (эталонный
  Python в этом месте честно поднимает OverflowError). Сейчас FPC молча
  возвращает пустую строку.
- В `Adapt` параметр `aDelta` — тоже переполняется через `I - aOldI`
  при wrap.

### Задачи

1. В `UTF8ToPunycode`: типы `aDelta`, `N`, `M`, `Q`, `K`, `T` и
   промежуточные `(M - N) * (aHandledLen + 1)` перевести на `QWord`.
2. В `PunycodeToUTF8`: `I`, `aOldI`, `W`, `D`, `N` — на `QWord`;
   `I - aOldI` вычислять без wrap (проверять `I >= aOldI`).
3. **Недостаточно просто расширить типы**: добавить явные проверки перед
   каждой опасной операцией, как в RFC-эталоне:
   `if aDigit > (High(QWord) - I) div W` перед `I += aDigit * W`;
   `if W > High(QWord) div (_BASE - T)` перед `W *= (_BASE - T)`;
   `if D > High(Cardinal) - N` / проверка `N <= $10FFFF` перед `N += D`
   (последнее полностью — в Этапе 2, здесь достаточно отказа).
4. Политика на переполнение (временная, до Этапа 3): возвращать `EmptyStr`
   из обеих функций. Не должно быть ни исключений, ни мусорного вывода.
5. Включить «ожидаемо падающий» `TestOverflowStress` из Этапа 0 и
   тест `'99999999999999999999' → EmptyStr`.

### Готово, когда

- `TestOverflowStress` проходит: длина 60015, round-trip тождественен.
- `PunycodeToUTF8('99999999999999999999') = ''` (защита, не «повезло»).
- `'invalid'` и 5000×`'a'` дают прежний **конформный** вывод (см. Этап 0).
- Все тесты Этапа 0 зелёные; benchmarks (`build_benchmarks`) запускаются.

## Этап 2 — Строгая валидация входа

**Цель:** невалидный вход никогда не превращается в мусорный вывод.

**Зависимости:** Этап 1 (общая политика «ошибка → EmptyStr»).

### Контекст (проверено зондами)

- `UTF8ToUnicodeArray` (fppunycode.pas ~74–139): не валидирует UTF-8.
  Обрезанная последовательность `C3 41` даёт фантомную кодовую точку
  U+0003, которая попадает в вывод паникода как контрольный символ
  (проверено: `#$C3'AB'` → паникод, содержащий `chr($03)`; round-trip
  ломается). 5-байтовые лиды `F8...` молча теряются. Overlong
  (`C0 80`), суррогаты (`ED A0 80`) и коды > U+10FFFF (`F4 90 80 80`)
  принимаются без проверки — последний ломает round-trip, потому что
  `UnicodeToUTF8Char` молча возвращает 0.
- `PunycodeToUTF8`, строки ~322–323: байты ≥ $80 в basic-части
  принимаются как «кодовые точки» и перекодируются в UTF-8 (проверено:
  `'x'+#$C3#$A4+'-aa'` → U+0080,U+0080,'x',U+00C3,U+00A4).
- `PunycodeToUTF8`, строки ~340–362: **нет проверки обрыва цифровой
  группы**. RFC 3492 (декодер): если внутри k-цикла ввод закончился до
  условия `digit < t` — это invalid input (эталонный Python поднимает
  «incomplete punycode string»). FPC молча трактует обрыв как финальную
  цифру: подтверждено, `PunycodeToUTF8('zzzzzzzzzzzzzzzzzzzz')` (20 z)
  возвращает 8 валидных CJK-символов.
- `PunycodeToUTF8`, строка ~371: `if I > aOutputLen then I := aOutputLen`
  — **мёртвый код**: после `DivMod(I, aOutputLen + 1, ...)` остаток
  всегда ≤ `aOutputLen`. Убрать как cleanup (полезной работы он не
  делает и не является источником мусора).

### Задачи

1. `UTF8ToUnicodeArray` → строгий парсер: отклонять (возвращая `EmptyStr`
   из верхней функции) любой из случаев: неверный lead-байт, обрезанная
   последовательность, не-continuation байт внутри последовательности,
   overlong-кодирование (проверять по длине формы), суррогаты
   `$D800..$DFFF`, кодовые точки > `$10FFFF`. Единая политика для всех
   случаев — никаких «частично пропущенных» байт.
   `UnicodeToUTF8Char`/`UnicodeArrayToUTF8` в этом случае не должны
   встречать невалидные точки, но проверку `> $10FFFF` оставить как
   защитную (возвращать ошибку, не 0-длину молча).
2. `PunycodeToUTF8`: basic-часть до последнего `-` — каждый байт должен
   быть < $80, иначе `EmptyStr`.
3. `PunycodeToUTF8`: добавить проверку обрыва группы — если внутренний
   k-цикл завершился по концу ввода (а не по `aDigit < T`), это
   невалидный вход → `EmptyStr` (подсказка: отличать выход по `Break`
   от выхода по условию `aPos > aInputLen`).
4. Убрать мёртвый зажим `I := aOutputLen` (строка ~371); защитную
   проверку `N <= $10FFFF` после `N += D` оставить/усилить из Этапа 1.

### Готово, когда (вход → ожидание)

| Вход                                            | Ожидание |
|-------------------------------------------------|----------|
| `#$C3'AB'` (encode)                             | `''`     |
| `'a'+#$F8#$80#$80#$80#$80+'b'` (encode)         | `''`     |
| `'x'+#$C3#$A4+'-aa'` (decode)                   | `''`     |
| `'ab%cd'`, `'%'`, `'%%%%%'` (decode)            | `''`     |
| 20×`'z'` (decode, обрыв группы)                 | `''`     |
| 20×`'9'` (decode, переполнение W/I)             | `''`     |
| `'invalid'` (decode)                            | конформный вывод `E69B8C E69B93 E69B90 E69B92 E69B8C` — НЕ менять |
| 5000×`'a'` (decode)                             | 5000 × U+0080 — НЕ менять |
| `'example'` (decode, валидный паникод без `-`)  | не пусто |
| все векторы Этапа 0 и property-тесты            | зелёные  |

## Этап 3 — Контракт ошибок API

**Цель:** вызывающий код может отличить ошибку от пустого результата.

**Зависимости:** Этапы 1 и 2 (ошибки уже детектируются).

### Задачи

1. В `fppunycode.pas` добавить парные функции (старые не удалять,
   они делегируют новым):

   ```pascal
   function TryUTF8ToPunycode(const UTF8Str: string; out Puny: string): Boolean;
   function TryPunycodeToUTF8(const aPunycodeStr: string; out UTF8Str: string): Boolean;
   ```

   Контракт: `True` — успех и `Puny` заполнен; `False` — невалидный вход
   (в т.ч. переполнение), `Puny` = `EmptyStr`. Пустая строка на входе —
   успех с пустым результатом (не ошибка).
2. В `fpidn.pas` аналогично: `TryUnicodeToIDN`, `TryIDNToUnicode`.
3. Документация контракта в интерфейсной секции обеих юнитов (краткие
   doc-комментарии): вход `UTF8ToPunycode` обязан быть валидным UTF-8;
   поведение старых функций при ошибке — `EmptyStr`; список причин отказа.
4. Внутри реализаций отказаться от «пустая строка = ошибка»: внутренние
   проверки возвращают Boolean, `EmptyStr` в старых обёртках — только
   как проекция ошибки.
5. Тесты: для каждой Try*-функции — позитивные (векторы Этапа 0) и
   негативные (набор Этапа 2) случаи.

### Готово, когда

- Все публичные функции имеют doc-комментарии контракта.
- Try*-функции покрыты тестами в обе стороны; старые функции работают
  как раньше (кроме новых строгих политик Этапов 1–2).

## Этап 4 — IDN-слой: `xn--` и потеря меток

**Цель:** `IDNToUnicode` не теряет метки и понимает любой регистр префикса.

**Зависимости:** Этап 3 (использует Try*-функции).

### Контекст (проверено зондами)

- `fpidn.pas`, строка ~57: `aParts[i].StartsWith('xn--')` — регистро-
  зависимо. `IDNToUnicode('XN--e1afmkfd.xn--p1ai')` возвращает
  `XN--e1afmkfd.рф` (метка не декодирована). DNS регистронезависим.
- Строка ~58: при неудачном декодировании `PunycodeToUTF8` возвращает
  `''`, и метка молча исчезает: `IDNToUnicode('test.xn--!!')` →
  `test.`; `IDNToUnicode('xn--')` → `''`.

### Задачи

1. Сравнение префикса — регистронезависимое
   (`StartsWith('xn--', True)` / `SameText`), сам префикс при декодировании
   нормализовать к нижнему регистру.
2. При неудачном декодировании метки **оставлять исходную метку как есть**
   (это восстанавливает input при round-trip и не даёт «схлопывать» домен).
3. Включить «ожидаемо падающие» тесты `XN--` и `xn--!!` из Этапа 0.

### Готово, когда

|-----------------------------------|-------------------------------|
| `XN--e1afmkfd.xn--p1ai`           | `пример.рф`                   |
| `Xn--Mnchen-3ya.com`              | `münchen.com`                 |
| `test.xn--!!`                     | `test.xn--!!` (метка сохранена)|

## Этап 5 — IDNA-маппинг и валидация меток

**Цель:** `UnicodeToIDN` выдаёт DNS-валидные метки: casefold, разделители,
запрещённые символы, длины.

**Зависимости:** Этап 4 (обработка меток), Этап 3 (сигнализация ошибок).

### Решённые рамки (зафиксировать в комментарии юнита)

- NFC-нормализация и полный Unicode casefold — **вне скоупа** (нужны
  таблицы Unicode); зафиксировать как ограничение в README.
- Нормализация pragmatic-MVP, ниже. Ошибки — через `TryUnicodeToIDN = False`.

### Задачи

1. **Разделители меток.** Перед сплитом по `.` замапить
   U+FF0E (．), U+3002 (。), U+FF61 (｡) → `.` (проверено: сейчас
   `'пример．рф'` кодируется одной невалидной меткой
   `xn--e1afmkfda6a40463c`).
2. **Casefold MVP.** ASCII `A-Z` → `a-z`; кириллица
   `$0410..$042F` → `+$20`, `$0400` (Ё) → `$0450` (ё); греческие
   `$0391..$03A9` (без спецслучаев $0345/$03A2) → `+$20`.
   Остальные — без изменений (документировать).
   Проверено: сейчас `UnicodeToIDN('ПРИМЕР.рф')` = `xn--h0afmkfd...`,
   после этапа должно быть `xn--e1afmkfd.xn--p1ai`.
3. **Запрещённые ASCII** (UseSTD3ASCIIRules-lite): отклонять метку,
   содержащую байты < $21 (контрольные + пробел) или любой из
   `<>"/\?#@:|` (список — именованная константа, легко расширить).
   Проверено: сейчас `'exa mple.com'` проходит как есть.
4. **Длины.** Каждая кодированная метка `xn--...` ≤ 63 байт; весь
   результат ≤ 253 байт; иначе отказ.
5. В `IDNToUnicode` зеркально: fullstop-варианты не трогать (они уже
   не встречаются в валидном xn--), но при декодировании обычного `xn--`
   ничего дополнительно не требовать.
6. Тесты: `ПРИМЕР.рф` → `xn--e1afmkfd.xn--p1ai`; `пример．рф` →
   `xn--e1afmkfd.xn--p1ai`; `exa mple.com` → отказ (False/пусто по
   контракту Этапа 3); метка из 70 символов → отказ; property-тест
   случайных доменов остаётся зелёным (генератор в нём не выдаёт
   запрещённых символов).

### Готово, когда

- Все тесты этапа зелёные; существующие тесты `TTestIDN` не регрессировали.
- Ограничения (NFC, полный casefold) описаны в README («Limitations»).
